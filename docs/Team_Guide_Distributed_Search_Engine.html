The whole project in 4 sentences

We build a small search engine across 4 Linux VMs that talk over a private network (ZeroTier). P1 feeds in a file of web pages; bad lines are thrown out and the rest go into versioned tables stored on P2's and P3's machines. P3's machine runs Spark jobs that build a word index and a popularity score (PageRank), then packages them as files. P4's machine downloads that package and answers searches on a web page.

1. The big picture

What each machine runs

MachineOwnerKeeps running in the backgroundIf it is off…
node1P1Nothing. It only starts the ingestion job.Only ingestion is blocked.
node2P2HDFS NameNode + DataNode, Spark WorkerNothing works for anyone.
node3P3Spark Master + Worker, HDFS DataNode, History ServerNothing works for anyone.

Who waits for whom

The work is a relay. Nobody starts their step until the person before them says so in the group chat.

Then the same relay again with the Phase 1 "changes" file, producing v2 and snapshot S1.

The words you need to know

TermMeaning in this project
ZeroTierA virtual private network so the 4 VMs can reach each other from different houses. Each VM gets a fixed IP ending .11–.14.
HDFSA file system spread over node2 and node3. Every file is stored twice (replication 2), so one machine can fail without losing data.
NameNode / DataNodeNameNode (node2) keeps the list of which file is where. DataNodes (node2, node3) hold the actual data.
SparkRuns a job in parallel. The Master (node3) hands out tasks; Workers (node2, node3) do them. If a worker dies, its tasks are redone elsewhere.
Apache IcebergThe table format. Every change creates a snapshot, so you can look at old versions (time travel) or undo a change (rollback).
Inverted indexword → which pages contain it, and how often. Like the index at the back of a book.
PageRankA page is important if important pages link to it. Damping 0.85, at least 10 rounds (we use 20).
BM25How well a page matches the search words. Repeating a word has diminishing returns; long pages don't get an unfair advantage. k1 = 1.2, b = 0.75.
Export / vNP3's checked package of results (Parquet files + manifest.json), in /exports/v1, /exports/v2, …
Final ranking formula Final score = 0.7 × (BM25 ÷ highest BM25) + 0.3 × (PageRank ÷ highest PageRank)

P1: Ingestion (Node 1)
Take the raw data file, throw away broken lines, keep only the newest version of each page, and load the clean pages into the Iceberg table.
Your machine runsNothing in the background. You only start jobs.
You wait forDay 1 to be finished (cluster green).
Your files to understandjobs/ingest.py, scripts/node1_ingest_phase.sh, scripts/inspect_dataset.py
You hand off toP3 after each phase.

Phase 0: the first data file

  1. Make sure ~/data/pages.jsonl exists on node1.
  2. Run: 
    cd ~/dse
bash scripts/node1_ingest_phase.sh 0 ~/data/pages.jsonl
    This uploads the file to HDFS (2 copies), then runs the Spark ingestion job. Takes a few minutes.
  3. Read the summary: lines read, how many were rejected and why, duplicates dropped.
    Worked if the end shows DONE. pages snapshot None -> <a long number> and an ingest_log table.
  4. Post "Phase 0 is in, P3 go".

Phase 1: the changes file only after P4 is serving v1

  1. Run: 
    bash scripts/node1_ingest_phase.sh 1 ~/data/changes.jsonl
    Newer versions replace old pages, deletes remove pages, and older (stale) versions are ignored.
    Worked if it prints actions={...} with some update / insert / delete, and ends with DONE.
  2. Run exactly the same command again. This proves that re-running changes nothing (idempotency).
    Worked if it says actions={'noop': …} and No page changes -> skipping MERGE.
  3. Post "Phase 1 is in, P3 go".

On demo day

  • Run Phase 0 and show the reject reasons.
  • Run Phase 1, then run it again to show nothing changes.
  • For the rollback demo, P2 may ask you to ingest a deliberately bad file as phase 2: bash scripts/node1_ingest_phase.sh 2 ~/data/bad.jsonl
What to say in the viva "Each line is parsed with json.loads on the Spark workers. Bad lines go to a rejects table with a reason, such as malformed_json or missing_url. For duplicates I keep the highest version, using a window function. Then I compare against the current Iceberg table, so only real changes go into one MERGE INTO, which is one atomic snapshot. That's why running a phase twice changes nothing. Finally I drop links that point to pages that don't exist."

What to say in the viva "HDFS keeps every block on both DataNodes (replication 2), so losing one DataNode loses no data. Iceberg stores its data and metadata in HDFS. Every commit is a snapshot, so we can time travel with VERSION AS OF and roll back a bad update. One honest weak spot: the NameNode on node2 is a single point of failure."

10. When things break

Problems are normal. Check the network first: most "the cluster is broken" problems are really "two machines can't reach each other".

Network / ZeroTier

On the machine with the problem, run:

sudo zerotier-cli info           # should say ONLINE
sudo zerotier-cli listnetworks   # should say OK and show your 10.147.17.x IP
sudo zerotier-cli listpeers      # DIRECT is good; RELAY means slow or blocked
ping node2
What you seeUsual causeFix
ACCESS_DENIED or REQUESTING_CONFIGURATIONMachine not authorizedP2 ticks Auth for it on my.zerotier.com.
OFFLINE, or peers stuck on RELAYThe Wi-Fi blocks ZeroTier (common on campus/college networks)Try a phone hotspot. If that works, it's the network: change network, or switch to Tailscale / same LAN (below).
Worked before, stopped after a rebootZeroTier service not runningsudo systemctl enable --now zerotier-one
Your IP changedNo fixed IP was assignedP2 sets fixed IPs .11–.14 in the web UI.
ping node2 fails but ZeroTier says OK/etc/hosts is wrongRe-run sudo bash scripts/setup_hosts.sh N.
The web pages (node2:9870 etc.) don't open on your laptopYour laptop isn't on the network or doesn't know the namesJoin the laptop to ZeroTier too, and use the IP (e.g. http://10.147.17.12:9870).
Plan B if ZeroTier won't work at all The code doesn't depend on ZeroTier. It only needs the 4 VMs to reach each other. You can use Tailscale (similar, often works where ZeroTier doesn't) or put all 4 laptops on the same Wi-Fi with the VMs in "bridged" network mode. Then: P2 puts the new IPs and subnet (ZT_SUBNET) in cluster.env and pushes; ALL pull, then re-run sudo bash scripts/setup_hosts.sh N and sudo bash scripts/install_node.sh N (this updates the firewall).
